# Session: 2026-07-14

## Goal
Capture a roadmap idea the user raised — **honouring photos on a DJI SD card** (single shots,
panoramas, RAW) when Conjoyn ingests directly from the card — and lock its scope before any code is
written. No implementation this session; capture + log to clear.

## Progress
- **Grounded the idea in real code** rather than speculating. Found that in `DJIFolderReader.read`
  (`01_Project/Conjoyn/Services/DJIFolderReader.swift` ~L67-83) the scan classifies only
  `mp4/mov/srt/lrf` as media — **every other extension hits `continue` and doesn't even land in
  `skippedNonDJI`**. So a `.JPG`/`.DNG` next to the clips is dropped with **zero trace**: a latent
  data-loss footgun if a user treats Conjoyn as their card-ingest tool and then formats the card.
- Confirmed the seams already exist: `DJIFilenameParser` returns a `mediaKind` enum with a latent
  `.other` slot (photos use the *same* filename grammar as video), the DCIM `resolveMediaFolders`
  descent already handles a dropped card root, and `VerificationService` already does checksum
  verification. So the feature needs **no new subsystems** — a `.photo` classification branch + a
  copy step.
- **Logged the decision** to `docs/decisions.md` (2026-07-14) with the scope guard: **preserve,
  don't process.** Two modes (SD-card = offer copy; watch-folder = surface count only), tiered
  scope (Tier 0 detect & surface → Tier 1 verified byte-copy → Tier 2 keep sets intact), and an
  explicit fence: **no** panorama stitching / HDR merge / RAW development.
- **Added a Backlog entry** to `docs/PROJECT_STATE.md` pointing at the decision.

## Decisions
- **SD-card photo handling = preserve, don't process** (full ADR in `decisions.md` 2026-07-14).
  Framed as **card safety** ("nothing on the card should be lost") rather than "photo support",
  which both gives it a coherent product story and bounds the scope. Designed to be camera-agnostic
  from the start so GoPro/Osmo stills ride the same path.
