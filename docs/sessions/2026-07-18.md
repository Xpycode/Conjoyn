# Session: 2026-07-18

## Goal
Diagnose and fix a user-reported crash in shipped 1.0.3: changing the output folder while
pending jobs sat in the queue killed the app (EXC_BREAKPOINT via
`+[NSApplication _crashOnException:]`, macOS 27.0 beta 26A5378n, M4 Pro).

## Progress
- **Root-caused from the crash report alone** (no debugger needed — the backtrace told the
  whole story): `chooseOutputFolder()` set `showApplyFolderPrompt = true` synchronously
  after `NSOpenPanel.runModal()` returned. On macOS 26+ the open panel is
  **ViewBridge-hosted** (its content is an out-of-process `NSRemoteView`, even for
  unsandboxed apps). Flipping the `@Published` flag in the same runloop turn made SwiftUI
  present the `ApplyFolderPopover` while the panel's remote view was still mid-teardown
  over XPC — the popover's window ordering posted a notification that the dying remote
  view's stale observer (`containingWindowWillOrderOnScreen:`) received, it threw, and
  AppKit's crash-on-exceptions trapped. Repro: add all groups from
  `2JOIN-IN/IN-M2A/DJI-M2A--2026-07-13/100MEDIA` to queue → change output folder to
  `2CULL-IN/IN-M2A` → crash.
- **Fix** (`ConversionViewModel.swift:293`): defer the flag flip past the teardown —
  `Task { try? await Task.sleep(for: .milliseconds(400)); showApplyFolderPrompt = true }`.
  Class is `@MainActor`, so the unstructured Task inherits main-actor isolation; a bare
  `main.async` is NOT enough because the teardown spans XPC round-trips. Why-comment left
  in code so the delay doesn't get "simplified" away.
- **Sibling audited, no change:** `WatchFoldersPanel.swift:86` also runs an `NSOpenPanel`,
  but its settings popover is user-toggled, never auto-presented after dismissal.
- **Verified:** clean xcodebuild cycle → BUILD SUCCEEDED; user re-ran the live repro in
  the debug build → **no crash** (race-class bug, so: one clean run + fully understood
  mechanism = high confidence, not absolute proof).
- **Committed `dcf44b8` to `main` + pushed.** Same commit gitignores `.claude/logs/` and
  `WORKING_NOTES.md` (session-local noise that was showing as `?? .claude/`).

## Decisions
- Tactical fix only (timing deferral), not a migration of `runModal()` →
  `begin(completionHandler:)` — the async-panel API would still need the same deferral, so
  it buys nothing for this bug. Not decisions.md-worthy.
